# Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the DDS §4.3 `Tools` core: inventory-bound registration and selection, deterministic wire names, lazy ordered wrappers, isolated concurrent invocation, and turn-safe error results.

**Architecture:** A catalog owns the mutable tool and wrapper registries; `forInventory` returns a facade over the same catalog with a cloned inventory membership set. Selection filters by `EntryName` and inventory type; invocation snapshots each call, lazily resolves selected wrappers in full-name order, and always returns a detached `ToolResult` for runtime failures.

**Tech Stack:** TypeScript, Node >=22.19.0, ESM, pnpm 12.8.1, Vitest; no new dependencies.

**Spec:** `docs/1 High-Level Design/1 High-Level Design.md` §5.1, §6.2–6.3, §8.2–8.5; `docs/2 Detailed Design Specification/2 Detailed Design Specification.md` §1.3, §2.1–2.2, §2.5, §3.9, §4.3, §4.5, §5.5.2, §5.5.4, §8.4–8.5; `docs/2 Detailed Design Specification/P0 Decision Table.md` P0-01, P0-10, P0-12.

## Global Constraints

- Core must not import daemon, protocol, filesystem, or network modules; `Tools` holds no session or turn state.
- Selection uses `EntryName` only; tool lookup and comparison use the complete `package#name` string.
- Wrapper names are applied in ascending UTF-16 code-unit order, independent of registration or selection order.
- The default wire-name encoder guarantees only the URL-safe `[A-Za-z0-9_-]` charset; provider-specific length limits are enforced by the adapter codec.
- Wrapper factories are lazy and cached as promises; neither registration nor `selected` may invoke a factory.
- `wireName` exists only at the adapter boundary. Session `ToolCall.name` remains `EntryName`.
- Runtime tool failures are results, not thrown errors; they must not terminate a turn.
- Only a `ToolDeniedError` thrown by the final `execute` produces `tool.denied`; generic final `execute` failures produce `tool.failed`; wrapper factory/composition failures map to `tool.wrapper_invalid`.
- Do not modify Context assembly, AgentLoopDriver, extensions, adapters, or daemon behavior in this plan.
- Run on `dev-codex`; never commit to `main`. Before every commit run `git status --short` and stage only the exact files owned by that task.

## Review Focus

- Concurrent calls that finish in reverse order must still map to their original call positions, and a shared wrapper factory must load once. Task 3 and Task 4 cover this.
- A caller mutating a registered declaration, inventory, `ToolCall.id/name/arguments`, selection, or returned result must not affect later calls or result association. Task 2 and Task 4 cover this.
- An unselected, missing, conflicting, or wrongly classified entry must not execute or wrap a tool. Task 2 and Task 3 cover this.
- A wrapper changing identity/metadata, failing to load, throwing `ToolDeniedError` during composition, or leaving no `execute` must yield a turn-safe result rather than calling the wrong implementation. Task 3 covers this.
- A pre-aborted or mid-call aborted signal is passed unchanged; cancellation remains cooperative and is never decided by `Tools`. Task 4 covers this.

## Fixed Interface Decisions

```ts
export type JsonSchema = JsonObject;

export interface EntryInfo {
  type: "tool" | "wrapper" | "skill" | "context";
  source: string;
  name: EntryName;
  description?: string;
  definition?: DefinitionSnapshot;
  definitionHash?: string;
}

export interface ToolDeclaration {
  readonly id: string;
  readonly source: string;
  readonly name: EntryName;
  readonly description: string;
  readonly parameters: JsonSchema;
  execute?: ToolFunction;
}

export interface ToolInvocationContext {
  sessionId: SessionId;
  workspace: string;
  signal: AbortSignal;
}

export type ToolFunction = (
  args: JsonValue,
  context: ToolInvocationContext,
) => Promise<ToolResult>;

export type ToolWrapper = (wrapped: ToolDeclaration) => ToolDeclaration;

export interface ToolInventory {
  hash: string;
  entries: EntryInfo[];
}

export interface Tools {
  forInventory(inventory: ToolInventory): Tools;
  registerTool(declaration: ToolDeclaration): void;
  registerWrapper(name: EntryName, factory: () => ToolWrapper): void;
  selected(selection: SelectionState): ToolDeclaration[];
  invoke(
    call: ToolCall,
    selection: SelectionState,
    context: ToolInvocationContext,
  ): Promise<ToolResult>;
}

export interface ToolsOptions {
  encodeWireName?: (name: EntryName) => string;
}

export function createTools(options?: ToolsOptions): Tools;
export function encodeWireName(name: EntryName): string;
export function decodeWireName(value: string): EntryName | undefined;
```

- Default `wireName = "t_" + base64url(UTF-16LE code units of EntryName)`, with `=` padding removed. It is injective, deterministic, uses only `[A-Za-z0-9_-]`, and is reversible; this does not guarantee provider-specific length compatibility. The adapter must enforce the active provider's length policy and use the same codec for `buildRequest` and `parseChunk`.
- `createTools()` creates one workspace-local catalog. `forInventory` shares that catalog's registrations but permanently snapshots the inventory hash and a map of its `EntryName -> type`; callers mutating the input inventory cannot change the facade.
- A catalog with no inventory bound sees all registered entries; service code must use one catalog per workspace and pass the frozen inventory facade to consumers.
- `selected` deduplicates selection names, keeps only registered `tool` entries present as `type:"tool"` in the bound inventory, excludes conflicts and wrappers, and returns detached declarations sorted by full `EntryName`.
- A wire-name collision marks the existing registration and the incoming name unavailable, then `registerTool`/`registerWrapper` throws `PiscesError("tools.wire_name_conflict", ..., {data:{wireName,names}})`.
- Wrapper factories are cached on first selected invocation, including rejected promises. Selected wrappers in a bound inventory without a registration produce `tool.wrapper_invalid`.
- Only `execute` may change through wrapping. A wrapper must return an object whose `id`, `source`, `name`, `description`, and JSON-equal `parameters` match its input; otherwise the call returns `tool.wrapper_invalid`.
- Error results have `content:[{type:"text",text:message}]` and `isError:true`. Missing/unselected tools and a final declaration without `execute` use `tool.failed`; only `ToolDeniedError` thrown by the final `execute` uses `tool.denied`; wrapper factory/composition/shape/immutable-field failures, including a `ToolDeniedError` thrown during wrapper composition, use `tool.wrapper_invalid`; other final `execute` throws use `tool.failed`.
- Stable messages are `Tool is not selected: ${call.name}`, `Tool has no execute function: ${call.name}`, `Tool execution failed`, and `Invalid tool wrapper: ${wrapperName}`. Final-`execute` `ToolDeniedError` preserves its explicit message; generic failures use `Tool execution failed`; wrapper-stage failures always use the `Invalid tool wrapper` message.
- Adapter boundary: the adapter must use one matching encode/decode codec for both request construction and response parsing, enforce the active provider's name-length limit, and surface an over-limit declaration before sending it. `Tools` collision detection covers only the encoder configured in `ToolsOptions`.
- `invoke` receives the signal but never checks it before or after `execute`. A tool may react cooperatively; an `AbortError` thrown by `execute` follows the normal `tool.failed` path unless the tool returns its own `ToolResult`.

## Completion Criteria

- An inventory-bound facade filters registered tool declarations and wrapper factories by frozen `EntryName`/type membership.
- Default wire names are deterministic, reversible, and use an adapter-safe charset; provider length enforcement belongs to the adapter, and collisions reject both names with `tools.wire_name_conflict`.
- `selected` never loads wrappers; invocation lazily loads each selected wrapper once and applies names in ascending full-name order.
- Immutable wrapper changes, wrapper load failures, and missing final `execute` return explicit turn-safe results.
- A final-`execute` `ToolDeniedError` maps to `tool.denied`, wrapper-stage denials map to `tool.wrapper_invalid`, generic final-`execute` throws map to `tool.failed`, and all thrown execution errors remain tool results.
- Concurrent invocations preserve caller order, do not share mutable per-call state, and pass `AbortSignal` unchanged.
- `invoke` preserves `ToolCall.id`, `ToolCall.name`, and `ToolCall.arguments`; wrapper argument mutation is confined to the per-call copy, and results remain associated by the original call id.
