# Context Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完整交付纯核心 Context：可审查确认的内存队列、分支声明选择、来源/技能物化、确定性请求裁剪压缩、A/B/C 并发提交和真实存储失败协调。

**Architecture:** Context 依赖现有 Sessions，不接触文件系统或网络。通过最小条目分类、来源和技能接口代替尚未实现的 Tools/Extensions；工具声明仅从会话/确认队列的定义快照恢复。锁与会话事件时钟由宿主注入，来源解析在锁外；持久化成功、出队与缓存更新在锁内完成。

**Tech Stack:** TypeScript、Node >=22.19.0、ESM、pnpm 12.8.1、Vitest；不新增依赖。

**Spec:** `docs/1 High-Level Design/1 High-Level Design.md` §2.2、§5.2–5.3、§6.4–6.5、§7.1；`docs/2 Detailed Design Specification/2 Detailed Design Specification.md`（下称 DDS）§2.3–2.5、§3.1、§3.5–3.10、§4.2、§4.5、§5.2–5.3、§7.5；`docs/2 Detailed Design Specification/P0 Decision Table.md` P0-01–04、06、09–14。同时阅读前序 core-foundation 与 session-store 计划。

## Global Constraints

- 实现语言为 TypeScript，运行时为 Node，包管理器使用 Pnpm，模块系统为 ESM。
- 核心层不得依赖服务层、客户端或运行环境。
- 会话树只追加，不删除；队列只存在内存，不做 WAL。
- 控制消息的 `content` 恰好包含一个 `text` 块，文本内容是 JSON 对象；控制消息不直接写入请求体。
- 所有持久化记录都带 `schemaVersion`；当前版本为 `1`。
- 已确认的全部 instruction 按分支/队列顺序保留，不以最新一条替代旧条目。
- 只有连续已确认前缀可装配；本次窗口之后确认的条目留给下一 step。
- 不实现 provider/adapter、Gateway、AgentLoopDriver、Concurrency、真实 Tools 执行、扩展发现或客户端协议；不创建这些模块的空壳。
- 用户已授权子智能体实施、主智能体审查与验收；无需再次向用户询问执行方法。按本计划实施，由主智能体安排各任务及审查。
- 后续在现有 `dev-codex` 执行，不切 main、不 push；每任务提交前 `git status --short`，只显式暂存本任务修改文件。

## Review Focus

- 锁外删除队列项后，消息、工具、来源、预算及 compaction 必须来自最终幸存批次；Task 5 覆盖删除 agent/声明和窗口冻结。
- 显式旧分支 parent 不等于文件默认末端；提交点后失败不能误认旧兄弟节点或重复写本批。Task 6、7 覆盖水位与同内容兄弟分支。
- toolCall/result 组跨过 instruction 时，整组不可删；已有 compaction 也不能吞掉 instruction。Task 4 覆盖保护指令与孤立结果。
- 来源忽略 AbortSignal 仍在稍后返回时，C 段必须拦住取消；事件回调抛错不能触发持久化失败补偿。Task 5、6 覆盖。
- 读出的 content/队列/事件对象被调用者修改，不能改变后续选择和持久化；未知或已出队 id 不靠无限墓碑识别。Task 1、2、6 覆盖。

## 审查门槛与设计澄清

本节所有澄清已由主智能体批准，Task 1 同步到 DDS 后执行依赖任务；不向用户重新询问。DDS 当前未提供的细节按以下裁定实施。

1. **已确认：** 增加 `unconfirm(): void`，清除所有尚未装配项的 `confirmedAt`，仅实际变化发布 queue.updated。取消由 signal 表示，`assemble` 在进入 A、B await 后、C 写入前检查；用 `signal.throwIfAborted()` 保留 reason，不新增取消协议码。`turn.empty` 仅表示最终无任何可见 kind=agent 消息；user-only 是有效首次上下文，不要求 system。同步澄清 DDS §3.6.2/§4.2.4 中“agent/system”措辞。
2. **已确认：** 不保存已装配 id 墓碑；所有不在当前队列的 id（含已出队/已删除）统一 `queue.entry_not_found`。同步 DDS §3.5/§3.9，替换不可实现的“出队后 reason=assembled”约定；已确认 edit 仍 `queue.entry_locked`、data.reason=confirmed。
3. **已确认：** 只有 `source=instruction` 的 agent/system 节点不可裁剪。system/create、来源/技能与普通消息均可裁剪；保留的 instruction 全部原样保留。已有/新 compaction 范围不得跨越 instruction；跨越的已有 compaction 忽略。包含 instruction 的工具组不可删，预算不够时失败。同步 DDS §4.2.6 的“非 system”矛盾措辞。
4. **已批准：预算。** `toolTokenReserve = estimateTokens(request.tools ?? [])`，空工具为 0；`estimateTokens(value)=ceil(new TextEncoder().encode(JSON.stringify(value)).length/3)`。消息总量按每条 Message 的估算值相加；B=`max(1024,contextWindow-maxOutput-toolTokenReserve)`。工具序列化字段仅 name/description/parameters，不计 runtime id/source；参数不隐式增加，模型取 C 段最新 meta.model。contextWindow/maxOutput 必须是有限非负整数，contextWindow>0，否则内部 TypeError。
5. **已批准：工具消息组。** 普通 agent 节点是一组；含 toolCall 的 assistant 到对应全部 toolResult 的最小连续区间是一组；交叠区间合并。一个 assistant 多调用一起保护，组内可含其他消息；任一 instruction 在区间内则整组不可裁剪。尚缺 result 的调用组整体保留；独立无对应 call 的 toolResult 不发送，判 `storage.corrupt`（不伪造结果）。同分支重复 call id 或重复 result 也 corrupt。cancel/control 不变成请求消息；结果 content 中嵌套 toolResult 只当内容，不作为外层调用配对。
6. **已批准：压缩确定规则。** 见 Task 4：UTF-8 token，Unicode code point 字符；可压缩范围为连续历史节点区间，不能跨 instruction/已有压缩/声明控制节点，不引用本批新 drafts。每区间独立满足 `节点数>=4 || 被丢弃消息估算tokens>=ceil(B/5)` 才压缩。摘要固定模板，不额外调用模型。先完成最旧组裁剪，再计算范围与摘要并重新算预算；摘要加入后继续裁最旧允许组直到稳定，仍超预算失败。
7. **已批准：新增内部错误。** 声明/默认 head 在一次重跑后仍变化用 `context.changed`，data.retryable=true；提交结果读不清时其他修改用 `context.pending_commit`，data.retryable=true。加入 DDS §3.9/§4.2/§7.5；后续 Gateway 原样映射，不在此新增协议实现。错误恢复后不再保留 pending。
8. **已批准：资源边界。** queue 单条与整队列按完整 QueueEntry JSON 的 UTF-8 字节计，分别 262144、1048576（整队列含数组标点）；确认也先计算完整候选队列再原子替换。来源/技能单节点内容按 DDS §3.1 限 262144 字节：仅裁 text/reasoning（含 toolResult 内文本），保留 code point 边界，末尾可见标记 `\n[truncated]`；不裁 toolCall.arguments。若不可裁字段使节点内容仍超 262144 字节，context.source_failed；Context 来源/技能不接受超过 256KiB 的内容，不允许不可裁字段占满事件预算。队列/声明不静默截断。session.updated 在核心按完整 EngineEvent UTF-8 字节 4194304 分批；每帧独立 seq，队列/选择通知按最终状态发布一次。
9. **已确定：** daemon 负责客户端 declaration definition 附加；Context.enqueue 是内部可信边界，接受已附完整 definitions，校验结构但不从实时 Tools 重新取定义。名称重复的 toggle 用 queue.duplicate_name 拒绝；这是 DDS §3.9 已有明确码，Task 1 统一 §3.5“去重”措辞。
