# Linux Local Daemon and Protocol Transport — Design

**Status:** Proposed; requires user approval before implementation planning or product-code changes. **Basis:** `dev-pi` at `58fec57` (Plan B complete). **Audience:** daemon and protocol maintainers. **Intent:** Make the existing in-process Gateway reachable by local clients without weakening the DDS same-user boundary.

## Approaches and decision

- **Chosen: Linux-first native credential check plus real Unix socket.** Add an in-repository, small C Node-API helper using Linux `SO_PEERCRED`, and a Linux-only daemon host. No unauthenticated fallback; macOS and Windows throw an explicit unsupported-platform error before binding. This gets a genuinely usable local transport on the current Linux platform with a reviewable security boundary.
- **Deferred: simultaneous Linux/macOS/Windows support.** macOS needs a tested `getpeereid` path; Windows needs restricted pipe DACL and peer SID verification, not a UID emulation. Doing both now multiplies native security work and test matrices.
- **Rejected: relying on socket mode alone, or an old `peercred` package.** Unix permissions protect the path, but do not implement the DDS peer-credential check. Unmaintained packages and runtime FFI hard-coded socket constants are less auditable than a small header-compiled Node-API helper.

## Goals, non-goals, constraints

**Goals:** A caller can start a daemon host programmatically, connect over a real Linux Unix domain socket, complete `protocol.hello`, issue the existing eight Gateway methods, subscribe/unsubscribe to session events, and stop cleanly. Enforce same effective UID before reading a single application byte. Tolerate fragmented/multiple NDJSON frames, concurrent requests, backpressure and crash-stale sockets. Preserve Plan B's marker recovery and turn lifecycle, with no new Core dependencies on daemon/protocol/Node networking.

**Non-goals:** No CLI commands, configuration loader, Windows/macOS transport, templates/clients/extensions inventory, queue edit/remove/clear, event replay, persisted sequence counter, user credential provider, network listener, or public unauthenticated transport. `startDaemon` receives `dataDir` plus external provider/tool/default configuration, constructs its own `SessionStore`, `ActiveTurnStore`, `EventBus` and `Concurrency`, then builds Gateway; it never accepts an injected store/markers whose path could differ from the lock path. A standalone distributable executable requires a subsequent configuration/composition stage. Existing eight Gateway methods remain unchanged for callers without a connection context.

**Non-negotiable:** Node >=22.19.0; TypeScript/ESM; in-repo plain C Node-API source (`<node_api.h>`) compiled with a pinned `node-gyp` dev dependency (no downloaded prebuilt binary), Linux only. Build script copies the `.node` output to a stable ignored `packages/daemon/native/peercred.node` path that source and compiled daemon modules can both resolve; build:daemon and documented test prerequisites build native first (direct `vitest run` does not trigger package scripts). Add a Linux CI workflow with Node 22.19, 24, 26 x64 matrix, native build, tests, TypeScript, Biome and boundary scans; no push means this workflow cannot be claimed as executed remotely in this stage. Verify Linux x64 locally and do not claim an unrun architecture works. Native build failure or unavailable peer UID means startup fails, not reduced authentication. The `dev-pi` branch, no push/merge without permission; preserve both existing SDD workspaces. Use TDD, fresh `deepseek-flash` implementer per task, independent task review and whole-stage review; six checks before each commit including the user-specified Core boundary scan.

## Architecture and public seams

```
client -- Unix socket (auth before bytes) -- NDJSON Transport -- connection dispatcher
                                                                | hello + request/response
                                                                v
                                                          Gateway.handle
                                                                | subscribe/unsubscribe
EventBus -> Gateway event bridge -> per-connection bounded send queues -> NDJSON Transport
```

- `@pisces/protocol` owns transport-neutral JSON request/response/event shapes, `PROTOCOL_VERSION`, version negotiation, strict byte-aware NDJSON codec constants/validation. It must not import `@pisces/daemon`, `@pisces/core` or Node filesystem/network APIs. Daemon retains domain-specific Gateway params/results; its request/response aliases can import protocol types instead of diverging. The JSON wire event is `{event: type, data: {sessionId, seq, at, ...payload}}` for known session event types; this matches the pre-budgeted core event projection (core tests pin the +1 byte `type`→`event` difference). Include `turn.cleanup_failed` as a safe, typed observable event.
- Linux `Transport` owns the `net.Server` accept path: it invokes its non-overridable production `peerUidFor(socket)` adapter before attaching a parser, then frames input and serializes output; it does not interpret Gateway method names. Tests can inject a reader only into an internal transport factory, never into public `startDaemon`. A connection dispatcher handles `protocol.hello` before any Gateway request; it dispatches all other methods to `Gateway.handle(request, connectionContext)` and sends the resulting response. It owns the per-connection pending-request set and closes/detaches on socket error, EOF or shutdown. Multiple requests can be outstanding, responses may return out of order, and events may interleave; a single ordered writer prevents byte-level interleaving.
- Gateway gains a connection-scoped extension without changing existing call sites: `handle(request)` still serves the eight methods and treats `session.subscribe/unsubscribe` as unknown without a live connection; with a registered connection it routes those two methods. `attach(connectionId, enqueueEvent)` registers the host-generated connection ID and its synchronous, nonthrowing send queue; `detach(connectionId)` removes it and all subscriptions but **does not cancel turns**; `dispose()` unsubscribes its EventBus handler only after host turns and connections have quiesced. A connection can subscribe to multiple sessions; repeated subscribe/unsubscribe is idempotent. Subscribe validates the session (including in-memory temporary sessions) under its session lock; session.read supplies the initial waterline. Event projection/enqueue is folded into the **existing one-per-Gateway EventBus handler**, after its `turn.ended` cleanup-phase transition; catch all projection/queue failures at the per-connection boundary so EventBus publish never fails due to one client. Publishing events never waits for socket I/O and one broken client must not fail a committed turn.

## Authentication and filesystem lifecycle

- The Linux-only native Node-API helper takes an accepted socket fd, uses `<sys/socket.h>` `getsockopt(SOL_SOCKET, SO_PEERCRED)` with a correctly sized `struct ucred`, and returns the kernel peer UID. The same addon applies `flock(LOCK_EX|LOCK_NB)` to an already-opened lock-file fd; lock ownership remains tied to that live fd (no PID-stale lock heuristics). Compile against Linux headers; no architecture-specific numeric socket constants. Unsupported platform, missing native binary, `getsockopt` failure or UID mismatch all fail closed.
- Node's accepted `net.Socket` has no documented peer-UID API; isolate the **undocumented** `socket._handle.fd` lookup behind a single daemon adapter. Validate an integer fd and do a bounded self-connection capability probe at startup, using a private ephemeral socket path under the verified `dataDir/run` after acquiring the lock but before binding `pisces.sock` (same-UID result required); remove that probe path by inode check, and test on supported Node versions. This prevents silent security regression when internals change but does not pretend the accessor is a stable Node API. Use `pauseOnConnect: true`; retrieve and compare peer UID with `process.geteuid()` **before** attaching the NDJSON parser or calling `resume()`. Reject all credential failures by destroying the socket without sending protocol bytes. Require `getuid() === geteuid()` at startup to avoid setuid identity ambiguity.
- Accept an absolute `dataDir`; refuse a symlink, foreign owner or group/world-writable **dataDir itself**; create it as `0700` if absent. Permit pre-existing ancestor directories such as `/tmp` (sticky `1777`) but never bind directly there. Create/verify a daemon-owned `dataDir/run` directory with exact mode `0700`, rejecting existing symlinks or insecure modes rather than chmodding them. Only bind `dataDir/run/pisces.sock`, checking encoded Unix path length <= 107 bytes; refuse too-long paths before touching any socket. The socket is `0600`; after binding verify with `lstat` owner, socket type and mode. Holding a `dataDir/run/pisces.lock` flock across bootstrap, bind and runtime is mandatory; do not unlink the lock file on stop (inode reuse could split ownership). A second process must fail without removing a live socket.
- After acquiring the lock, an existing socket path is removed only if `lstat` confirms a same-owner socket (not a symlink or regular file) **and** a bounded probe connection (1s default) reports `ECONNREFUSED`/`ENOENT`; a successful connection or timeout means startup fails without unlinking. On stop/failed startup, unlink only the socket inode this instance bound (`dev`/`ino` match), then release the lock fd. Crash recovery leaves the lock automatically released; the next owner safely handles stale socket and runs Plan B's marker recovery before accepting requests.

## Framing, handshake and error rules

- Split incoming bytes on `0x0a` with a bounded accumulator; enforce `MAX_FRAME_BYTES = 8 MiB` (UTF-8 bytes including terminator) before `JSON.parse`. Use fatal UTF-8 decoding, reject malformed JSON, non-object/array envelopes and invalid `id`/`method`/`params` as `protocol.invalid_json` or `protocol.invalid_request` with safe fixed messages. For unparseable/invalid IDs use `id:""` as a documented error sentinel; never echo raw input. Oversize frames get `protocol.frame_too_large` where a response can safely be sent, then the connection closes. Outbound responses/events have a 4 MiB serialized-byte cap; any unexpected over-budget outbound value fails safely without leaking content. Tests cover Unicode boundaries, CRLF policy (only literal LF framing), complete and partial lines, and poisoned method names.
- First valid request must be `protocol.hello`; any earlier other method returns `protocol.hello_required` and keeps the connection eligible to hello. Hello validates `versions: string[]`, prefers the first compatible client-advertised `MAJOR.MINOR.PATCH` with the server's major and minor not higher than server's; mismatch returns `protocol.version_mismatch`, **flushes that response, then closes**. Duplicate hello after success returns `protocol.invalid_request`. A successful connection pins its negotiated version until close. Invalid-json frames do not turn into a handshake; repeated errors and idle pre-hello clients are bounded by an explicit timer/connection limit, without prematurely accepting application requests. `Gateway.handle` keeps the Plan B safe error mapper: PiscesError→code/message; unknown errors→fixed `internal.error`; no cause, payload or credential leakage.
- `Connection.send` queues complete encoded frames, flushes serially on `drain`, and has an 8 MiB queued-byte default budget (tests inject a smaller budget). Before hello, allow at most 64 concurrently open sockets and 5s per connection; a version-mismatch error gets up to 1s to flush before close. Do not impose an idle timeout on authenticated streaming turns. For all limits, expose narrow internal test options, not an unauthenticated public bypass. Queue overflow, write errors or an unexpected over-budget event close **only that connection**, detach its subscriptions, and leave turns running; a reconnecting client must resubscribe then read. EventBridge catches all enqueue/encoding failures so no subscriber exception propagates into synchronous EventBus publication. No silent drop-and-continue or unbounded memory growth. `session.subscribe` installs the subscription before returning its response; events and responses may interleave. No event replay; initial load is subscribe→read, with the first `session.read.seq` as waterline and subsequent pages merged by id, never advancing that waterline.

## Host start/stop/state and failure policy

- Public API: `startDaemon(options: { dataDir: string; providers: ProviderManagement; providerHost: ProviderHost; defaults?: SessionDefaults; /* existing optional tool/skill/source factories */ }): Promise<DaemonHost>`; `DaemonHost` has `socketPath`, `initializationIssues`, `recoveryIssues`, `status(): {state: "running"|"quiescing"|"stopped"; activeTurns: number}`, and `stop(): Promise<void>`. The host creates one store, marker store, lock, EventBus, Concurrency, Gateway and Unix listener; no external store/marker injection in this public constructor. Internal transport and host factories may receive small fakes for tests but must not expose a production auth bypass. Order: validate Linux and dataDir → verify/create private runtime dir → acquire its flock → probe native peer creds on a temporary path → handle stale socket → `bootstrapGateway` (store initialization + turn recovery) → bind and verify public socket → accept connections. On any failure, close what was acquired in reverse order, leaving the lock file itself in place. Errors are safe `PiscesError` codes: `daemon.unsupported_platform`, `daemon.native_unavailable`, `daemon.peercred_probe_failed`, `daemon.lock_busy`, `daemon.insecure_directory`, `daemon.socket_live`, `daemon.socket_path_too_long`, `daemon.stop_incomplete`; other internal failures map to `daemon.start_failed` without raw native causes. Synchronize the DDS §3.9 table with these codes. `status()` never reports secret config.
- `stop()` is idempotent on success. First mark `quiescing`, gate off **new request frames before they enter the pending set**, and stop accepting new connections; keep connections already admitted until their in-flight Gateway operations finish. Await the pending set **before** `Concurrency.cancelAll(timeout)` so a queued `turn.start` cannot register after the cancellation snapshot; if pending requests do not settle within 5s, throw `daemon.stop_incomplete` and retain lock/socket inode, Gateway and quiescing state (retry later). Once drained, call `cancelAll(5000)` once per stop attempt, await active-turn unregistration including marker cleanup, and **check** `activeTurns().length === 0` (a timeout resolves silently). If any turn remains, throw the same incomplete-stop error and retain the lock and quiescing state; a `cleanup_failed` turn cannot be claimed as gracefully stopped, and retry may remain unsuccessful until process termination/restart recovery. If all settled, close/detach connections (discard un-sent responses on closed connections), dispose the Gateway listener, wait for `net.Server.close()`, unlink only our socket inode, release lock fd and mark stopped. An incomplete stop does not authorize silently force-killing the process; operator termination remains a separate explicit action. Closing a client connection alone only detaches subscriptions, not turns.

## Tests and documentation

- Native/Linux security tests: self-connection UID accepted; mandatory injected mismatch/missing fd/getsockopt error denied before parser; cross-UID subprocess via unprivileged user namespace (`unshare -Ur`) if enabled, explicitly skip only that OS-level test if disabled; permissions, symlink/non-socket refusal, stale vs live socket, two processes racing startup, inode-preserving cleanup and crash/restart marker recovery. For spawned process tests, build TS+native first and launch built `dist/*.js` fixtures (never rely on Vitest alias resolution in a child Node process). Commit the Linux Node 22.19/24/26 CI matrix, run the available local Node version, and report any other matrix entries as unverified until CI runs; never claim unrun versions verified.
- Protocol unit tests: fragmented/multiple UTF-8 frames, exact limits, invalid envelope and error sentinel, hello ordering/version/flush-and-close, unknown/inherited method routing, concurrent response/event serial writes and bounded backpressure.
- Real-socket integration: bootstrap before first accepted request, hello then `provider.list`/session create/read/turn, two clients/multiple session subscriptions, unsubscribe/disconnect not cancelling a turn, subscribe→read sequence waterline, event isolation and forced slow-client overflow, `stop()` including cancellation timeout and cleanup failure. Failure paths must prove no unauthenticated request runs and no native raw error is sent to clients.
- Update DDS §§2.6, 3.1–3.3, 3.4.5, 3.8–3.9, 5.1, 5.3, 5.9 and HLD §8.1 only where the implementation differs: Linux-only support for this stage, actual public host API, operational limits, identity checks and shutdown failure semantics. Target Windows named-pipe/SID support stays explicitly future-facing. Add an operator note for native compilation/Node version support and lack of standalone CLI.

## Prior-stage residuals and risks

- Add a direct persisted-session marker-write-failure test while modifying Gateway integration; ensure no provider request is made. Reconcile pre-existing DDS `turn.not_found` and future `SessionRuntime.subscribers` labels when synchronizing DDS. No promise to fix the temporary-session commit-to-marker crash window; it remains documented and unrecoverable until a separately designed persistence change.
- Primary risk is the private `_handle.fd` contract: startup probe, fail-closed guard, pinned supported Node matrix and a narrow adapter make failure visible, but do not make Node internals stable. Native build/deployment is a new operating requirement. Subscription push must not convert client backpressure into `event.publish_failed` after a record commit. Failed graceful stop retains the lock rather than falsely reporting clean shutdown.
